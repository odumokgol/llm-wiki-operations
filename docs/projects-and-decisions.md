# Projects and Decisions

## Project Hub

A project page should be an operational control surface, not a transcript. Keep these sections visible near the top:

- Goal / Why now
- Current phase
- Current status
- Next actions
- Blockers and risks
- Decisions
- Evidence and related pages
- Last verified
- Context Bundle

Use `status`, `last_verified`, `next_review`, and `review_state` so stale project state is visible.

## Decisions

A decision page records:

- the decision;
- date and scope;
- alternatives considered;
- rationale and evidence;
- rejected or deferred options;
- approval status;
- review/reversal conditions;
- affected projects and pages.

Do not turn a draft, hypothesis, or recommendation into an approved decision without explicit confirmation.

## Cascade handling

Search all affected domains before updating a decision or project. For `cascade`, list candidate pages first. Update only after review, then rerun health checks and record the change in the log.
