# Memory Rules

## Purpose

The Wiki is the durable memory layer. Memory is not a dumping ground for every conversation, and GitHub is not a personal-data archive.

## Preserve

Preserve information when it is:

- a durable user preference or correction;
- an approved decision and its rationale;
- a reusable project constraint or workflow;
- a source-grounded concept likely to be reused;
- an unresolved question that materially affects future work;
- a validated failure lesson or operating boundary.

## Keep local or discard

Keep information local to the current task when it is:

- a transient progress update;
- a one-off draft or temporary reasoning step;
- an unconfirmed hypothesis;
- duplicate material already represented elsewhere;
- irrelevant to future retrieval.

Discard or do not promote content when its evidence is insufficient, its privacy risk is high, or it has no foreseeable reuse.

## Conversation handling

If conversation archiving is enabled in the canonical Wiki:

- preserve raw conversation separately from its structured summary;
- redact tokens, passwords, API keys, OAuth data, and unnecessary personal data;
- do not treat an agent-generated subtask transcript as a user-approved decision;
- keep profile boundaries separate;
- distinguish current session context from durable knowledge.

## Google Drive boundary

Google Drive is a ChatGPT-facing copy only. It should contain approved, non-sensitive, reusable knowledge. Do not place there:

- raw company documents or customer information;
- private relationship records;
- complete email archives or session exports;
- credentials or secrets;
- sensitive personal data;
- material whose sharing status is unclear.

## Conflict and freshness

When two pages disagree:

1. compare source dates and evidence status;
2. identify the canonical system;
3. preserve both claims when the conflict is genuine;
4. mark the page for review rather than silently overwriting;
5. update the secondary copy only after the canonical decision is clear.

## Quality test

Memory quality is measured by whether Hermes or ChatGPT can retrieve the correct page, use the latest approved decision, cite the evidence boundary, avoid project/profile confusion, and say when the answer is unknown.
