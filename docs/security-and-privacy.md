# Security and Privacy

## Repository boundary

This repository is a handbook, not a personal-data archive. Keep the canonical Wiki separate and private.

Never commit:

- `.env` files, tokens, passwords, certificates, OAuth data, or connection strings;
- raw emails, customer records, meeting transcripts, or session exports;
- relationship journals or other sensitive personal records;
- Siemens/company documents or confidential information;
- private datasets, browser storage, or generated artifacts containing user data.

## Safe examples

Examples must be synthetic, minimal, and clearly labeled. Replace real names, URLs, identifiers, dates, and paths. Do not use copied fragments from private sources merely because they appear harmless.

## Approval boundary

Read-only scans and documentation changes are low risk. Treat repository creation, visibility changes, external integrations, policy changes, data movement, and large structural edits as approval-sensitive actions.

## Profile isolation

Do not mix default and wife profiles, their credentials, sessions, memories, or Wiki paths. Do not publish Hermes session data while documenting Hermes-related workflows.
